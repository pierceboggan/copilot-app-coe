# Launch comms templates

Many people with a Copilot seat do not know the Copilot app exists. These templates assume a broad launch: the app is on for everyone with a seat on launch day. Send them in order and edit the bracketed parts.

---

## 1. Launch email

**Subject:** The GitHub Copilot app is on for everyone, starting today

Hi everyone,

You can now use the GitHub Copilot app, a desktop app that runs several Copilot agent sessions at once. Each session works on its own branch, so you can fix a bug, review a pull request and prototype an idea at the same time.

It uses the Copilot seat you already have, and it is turned on for everyone in <organization> today. It isn't only for code. People here use it to research a topic, analyze a spreadsheet, draft a deck and triage feedback, too.

Our approved plugins, skills and connectors are already installed for you.

**Try it in 15 minutes:**

1. Install the app: <link to docs or internal software portal>.
2. Sign in with your work GitHub account.
3. Open a small issue from **My work**, choose **Plan** mode and run this prompt:

   > Read the linked issue and the code it touches. Propose a plan that lists the files you will change and the tests you will add. Wait for my approval before writing code.

Questions go to <channel>. Office hours run every day this week at <time>, then weekly. Your team's champion is running a 30-minute demo this week.

<Sponsor name>

## 3. "Try this" prompts for team channels

Post one a week. Each is short enough to run in a few minutes.

- **Monday, engineers:** "List my open pull requests, with CI status and unresolved review threads. Put anything that needs me first."
- **Tuesday, everyone:** Attach a CSV and ask: "Open this in an Excel canvas, add a summary row and chart the top five values."
- **Wednesday, PMs:** "Summarize issues labeled feedback from the last 30 days into themes with counts."
- **Thursday, leads:** "Draft my weekly status from merged PRs and closed issues. Keep it under 200 words."
- **Friday, everyone:** Run `/security-review` on your in-progress branch before you leave.
