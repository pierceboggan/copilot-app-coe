# Demo day and lunch-and-learn formats

## Lunch-and-learn (45 minutes, any audience)

| Time | Segment |
| --- | --- |
| 0:00 | Why this matters to our team, in one slide |
| 0:05 | Demo 1: issue to pull request in Plan mode |
| 0:15 | Demo 2: a non-code workflow, such as a CSV analysis in an Excel canvas |
| 0:25 | Everyone runs a starter prompt on their own machine |
| 0:40 | Questions, and where to get help |

**Script notes for the presenter**

- Use a real issue from a team repository, not a toy example.
- Narrate the plan review out loud. People learn the most from watching you decide what to change.
- Show one thing going wrong and how you recover. It builds trust.

## Demo day (90 minutes, admins and decision makers)

The goal is a decision, not applause. Invite admins, security partners, engineering directors and finance.

| Time | Segment | Presenter |
| --- | --- | --- |
| 0:00 | Program goal and pilot results so far | Sponsor |
| 0:10 | Three internal workflows, 10 minutes each, live | Champions from three different roles |
| 0:40 | How it is governed: rings, repository configuration, connectors, sandboxes | Admin and security partner |
| 0:55 | Metrics: activation funnel and outcome trends | CoE lead |
| 1:05 | Open questions | Everyone |
| 1:20 | Decisions: next ring, budget, policy changes | Sponsor |

**Preparation checklist**

- [ ] Each demo rehearsed on the demo machine the day before.
- [ ] Backup recording of every demo.
- [ ] Governance answers prepared from the admin readiness package.
- [ ] Customer and personal data removed from all demo content.
- [ ] Decision list drafted and shared with the sponsor in advance.
