The GitHub Copilot app is a desktop app for agent-driven development. You run several agent sessions at once, each isolated on its own branch, and take work from an issue to a merged pull request without switching tools. You can also use it with no repository at all, for documents, data and research.

<h2 id="core-ideas">1. Learn the core ideas (5 minutes)</h2>

| Concept | What it means |
| --- | --- |
| **Project** | A repository or folder you work in. Use a local folder, pick one from GitHub, or clone from a Git URL. |
| **Session** | One agent working on one task. Each session gets an isolated workspace, so sessions can run in parallel without conflicts. |
| **Location** | Where a session runs: a new working tree, your local repository, or a cloud sandbox hosted by GitHub. |
| **Mode** | How much autonomy the agent has. **Interactive** works with you step by step. **Plan** proposes a plan for your approval first. **Autopilot** works on its own. |
| **Chats** | Conversations with no branch or working tree. Good for brainstorming and questions. |
| **My work** | Your issues and pull requests in one place. Start a session from any of them. |
| **Automations** | Saved prompts that run on a schedule, on an event or on demand, locally or in the cloud. |
| **Canvases** | Shared, agent-driven artifacts and interfaces that you and the agent work on together. |

<h2 id="install">2. Install and sign in (10 minutes)</h2>

Follow the [Copilot app documentation](https://docs.github.com/en/copilot/how-tos/github-copilot-app) to install the app, then sign in with the GitHub account that has your Copilot seat.

| Where your account lives | How to sign in |
| --- | --- |
| GitHub.com | Sign in with your GitHub.com account. If your organization uses SAML single sign-on, authorize the session when prompted. |
| GitHub Enterprise Cloud with data residency (GHE.com) | Choose **Use GitHub Enterprise** and enter your `*.ghe.com` hostname. |
| GitHub Enterprise Server | Not supported today, per the [quickstart](https://docs.github.com/en/copilot/get-started/quickstart-copilot-app). Check with your account team before you plan a rollout. |

<LessonCheck module="first-hour" lesson="install" />

<h2 id="project">3. Add a project (5 minutes)</h2>

In the sidebar, click **+** next to **Projects** and choose a repository you know well. A repository with tests works best for a first try.

No repository? Start a chat instead, attach a CSV or your notes and ask for a result:

<PromptBlock mode="interactive" prompt="Open the attached CSV in an Excel canvas. Add a summary row, a pivot by category and a chart of the top five values. Explain each formula you add." />

The [business and operations](/roles/business-ops/) role page has more workflows like this.

<LessonCheck module="first-hour" lesson="project" />

<h2 id="plan-session">4. Run a Plan mode session (30 minutes)</h2>

Pick a small, real issue. Open **My work**, select the issue and click **New session**. Choose **Plan** mode and use this prompt:

<RepoSetting />

<PromptBlock mode="plan" prompt="Read the linked issue and the code it touches. Propose a plan that lists the files you will change, the approach, and the tests you will add or update. Wait for my approval before writing code. After approval, implement the change and run the relevant tests." />

Read the plan carefully. Ask for changes if anything is off, then approve it. Watch the agent work, and steer it in the conversation when needed.

<LessonCheck module="first-hour" lesson="plan-session" />
